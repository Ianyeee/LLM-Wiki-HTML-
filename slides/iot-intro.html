Module 1 ・ 訊號擷取 SPS30 & SHT20

系統的靈敏五官：把空氣微粒翻譯成數位數字

微控制器只懂得 0 與 1，必須依賴感測器的五步訊號轉換管道：

⚙️ 訊號轉換五部曲 (Signal Pipeline)

  1. 1 偵測物理現象：雷射光束照射空氣微粒產生散射。
  2. 2 轉換為電訊號：光電二極體產生微安培級光電流。
  3. 3 放大與 ADC：運算放大器放大，ADC 轉換為數位碼。
  4. 4 校準換算：內建微晶片依原廠曲線補償溫濕度漂移。
  5. 5 數位通訊傳輸：以 I2C / UART 協定將精準數值傳予 MCU。

感測器選型特點

本案例選用 Sensirion SPS30，具備內部專屬抗積灰清潔風扇演算法，能同時計算 PM1.0、PM2.5、PM10 的質量濃度。

💡 新手生活化比喻

感測器就像晶片的「眼睛、鼻子與皮膚」―― 人類皮膚感受冷熱、鼻子聞到煙塵；感測器把空氣中肉眼看不到的微粒，精確翻譯成晶片能看懂的度量衡。

Module 2 ・ 運算中樞 STM32 + ESP32

指揮官與偵察兵：STM32 與 ESP32 的雙腦默契

高頻即時硬體控制與無線連網協定並存時，雙晶片分工是工業界的黃金標準：

總指揮官

STM32 (Cortex-M4)

專注於即時控制與演算法決策大腦

  • 運行滑動模態控制（SMC）與模糊控制（Fuzzy）。
  • 以高階硬體定時器精確輸出 PWM 控制抽風馬達轉速。
  • 中斷反應延遲達微秒級，保障系統硬體安全連鎖。
通訊前哨

ESP32 (Wi-Fi & BLE)

前線數據採樣、濾波與網路閘道

  • 週期性向 SPS30 讀取 PM2.5 並進行滑動均值濾波。
  • 將感測數據封裝為標準 JSON 格式字串。
  • 透過 2.4 GHz Wi-Fi 以 MQTT 協定發布至雲端。

💡 新手比喻： STM32 就像「作戰指揮官」，坐在安全指揮部調度大局；ESP32 則是「前線偵察兵兼通訊員」，負責採集敵情灰塵並背著無線電向總部回報。兩者分工讓控制不卡頓、通訊不掉包！

Module 3 ・ 資料封裝 JSON Payload

標準化物流單：為什麼物聯網系統首選 JSON？

在「傳輸效率」、「跨平台相容」與「除錯便利」三者之間取得最佳平衡：

● sensor_payload.json ESP32 發送格式 
{
  "device_id": "ESP32_LAB_01",
  "timestamp": 1732018800,
  "data": {
    "pm25": 24.5,
    "temperature": 26.8,
    "humidity": 58.2
  },
  "status": {
    "fan_duty": 45,
    "alert_level": "NORMAL"
  }
}

1. 跨語言原生相容

ESP32 的 C++、伺服器的 Python、網頁的 JS 全都原生支援解析，無需額外轉譯層。

2. 自我描述與高可讀性

Key-Value 結構清晰，工程師除錯時直接肉眼閱讀 Log，省去十六進位解碼痛苦。

3. 擴充不破壞向下相容

未來新增 CO2 欄位時，舊版接收程式碼只需忽略未知 Key，系統依然穩健運作。

💡 生活化比喻： JSON 就像貼在包裹外的「標準快遞托運單」，欄位清楚寫著寄件人是誰、重量幾公斤。不論各國海關講什麼語言，看到標準托運單立刻懂得如何派送。
Module 4 ・ 訊息派發 MQTT Pub / Sub

高效率推播：不用逐一打電話的 Pub / Sub 機制

解耦發布者與接收者，固定標頭僅需 2 Bytes，專為資源受限物聯網而生：

📡

Publisher (發布者)

ESP32 感測節點

只管將訊息推送給主題 lab/env/pm25，完全無需理會誰會接收。

🏢

Broker (代理人伺服器)

Mosquitto / EMQX

訊息轉運中樞，負責維護連線，並精準推播給有登記該主題的訂閱者。

💻

Subscriber (訂閱者)

前端網頁 / 本地閘道器

向 Broker 登記感興趣主題，一旦有新資料即刻收到被動推播。

極輕量標頭 相比 HTTP 龐大 Header，MQTT 標頭僅 2 Bytes，大幅節省電力與 4G/5G 流量。
靈活主題階層 支援 +（單層）與 #（多層）萬用字元，例如訂閱 lab/# 可接收整間實驗室所有設備。
💡 生活化比喻 如同 YouTuber（發布者）把影片上傳到頻道（Topic），YouTube（Broker）自動向開啟小鈴鐺的觀眾（訂閱者）發送推播！
Module 5 ・ 終端視覺化 Chart.js & WebSockets

駕駛座的儀表板：前端視覺化與圖表動態渲染

數據抵達終端瀏覽器後，透過三大步驟化為即時直觀畫面：

Step 1. 長連線接收

MQTT over WebSockets 建立持續雙向通道，摒棄重複 HTTP 輪詢。

Step 2. 解析與清洗

JSON.parse() 還原物件，並驗證 PM2.5 數值是否在合理物理區間。

Step 3. FIFO 佇列渲染

Chart.js 畫布保留最新 20 筆紀錄，先進先出推移更新平滑折線。

即時狀態指標：正常 (PM2.5: 18.2 μg/m³)

抽風風門轉速：35% (SMC 滑動模態動態調整中)

💡 新手比喻： 就像超跑的數位儀表板，駕駛不需要懂得引擎噴油嘴的微安培電壓，只要輕瞄儀表板指針，就能立刻洞悉車況安全！

Conclusion ・ 總結與核心思維 Key Takeaways

工程手帳回顧：構建穩健物聯網系統的三大基石

從這套「雙晶片 + MQTT + JSON + 網頁視覺化」架構中，我們學會的三個核心哲學：

🎯

邊緣分工 (Edge Allocation)

專門晶片做專門的事。STM32 負責高即時閉迴路決策，ESP32 負責聯網與採樣，確保控制零死角。

🔗

鬆散耦合 (Loose Coupling)

以 MQTT 與 JSON 為中介。網頁改版不必更動微控制器韌體；硬體升級感測器亦不破壞網頁前端。

📖

手帳思維 (Engineering Rigor)
