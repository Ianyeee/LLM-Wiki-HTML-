04. 物聯網資料格式 JSON (JSON Payload)

Overview 簡介： JSON 以 Key-Value 結構為基礎，在「輕量傳輸效率」、「跨平台跨語言相容性」與「開發除錯便利性」三大維度之間取得了公認的最佳甜蜜點。

1. 為什麼物聯網系統首選 JSON？

跨語言原生相容

ESP32 的 C++、後端的 Python、前端的 JS 全都內建支援，免去編譯轉譯成本。

肉眼除錯極佳

純文字自我描述，工程師在 Serial Monitor 或網路 Log 一眼看懂數值含義。

向下相容性高

新增 CO2 或 VOC 欄位時，舊版接收程式碼只需忽略未知 Key，系統永不崩潰。

2. 真實感測器 Payload 封包結構

{
  "device_id": "ESP32_LAB_01",
  "timestamp": 1732018800,
  "data": {
    "pm25": 24.5,
    "pm10": 38.2,
    "temperature": 26.8,
    "humidity": 58.2
  },
  "status": {
    "wifi_rssi": -62,
    "fan_duty": 45,
    "alert_level": "NORMAL"
  }
}

3. 新手生活化比喻 (Novice Analogy)

💡 國際標準化的「宅配包裹托運單」：

Raw Data（一串雜亂的二進位位元組）：就像寄件人把一堆零件胡亂塞在箱子裡，上面什麼都沒寫，收件人打開來根本不知道哪個螺絲是配哪個螺栓。

JSON 格式：就像在包裹外面貼上一張格式規範統一的「黑貓 / 順豐托運單」。上面清楚印著【寄件人（Key）：ESP32】、【物品名稱（Key）：PM2.5】、【測量數值（Value）：24.5】。不管快遞員講中文、日文還是英文，一眼看過托運單就知道包裹裝什麼、該怎麼配送！
